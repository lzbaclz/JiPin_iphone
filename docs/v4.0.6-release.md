# 极拼 4.0.6（构建 10）

修复多图长拼在编辑器清楚、保存后模糊，以及画布顶部 LIVE 标记与输出尺寸重叠的问题。主 App 和扩展统一为 4.0.6 / 10。

## 原因与修复

用户提供的 JPEG 实际为 234×1440，编辑器显示的照片尺寸为 1440×8855。旧 Live 导出把整张长图缩到长边 1440，再用压缩视频的中间帧作为照片封面，导致照片细节一并丢失。

- 保存和分享生成正式资源时，照片封面从导入的原照片、Live 原始关键照片重新合成，保留照片尺寸和编辑效果。轻量预览不会被当成正式成品保存。
- 长图动态最长边从标准 1080 / 高清 1440 提高到 1920 / 3840，同时限制在 4,194,304 像素，视频宽高为偶数。其他模式的动态规格保持原值。
- 静态照片仍受已有 16,384 长边、16,777,216 像素限制。视频读帧、缓存和预处理资源先释放，再渲染完整照片，避免同时保留两套高分辨率画面。
- 配对照片保留与视频一致的内容标识，输出继续通过原生 PhotoKit 加载检查。照片和视频可以使用不同分辨率，界面分别显示两者的实际尺寸。
- 顶部 LIVE 和照片尺寸放在同一个自适应布局中，空间不足时分行，避免两个独立叠加层互相压住。保存后返回编辑器使用相同布局。
- 保留 4.0.5 的时长自动刷新、连续变化合并、关闭重开和保存后返回编辑器行为。

对应 1440×8855 的长图，新版高清照片为 1440×8855，动态为 624×3840。旧版已保存的低清文件需要从原草稿重新导出，无法从缩小的 JPEG 恢复原始细节。

## 验证记录

验证目录：`build/Validation-export-quality/`。使用原创示例和合成测试素材，用户照片未加入仓库或安装包。

核心新增覆盖：五张照片（三 Live 两静态）的横竖输出、全分辨率细线对比、1440×8855 奇数高度、标准与预览尺寸区分、20 张长图和视频像素限制，以及系统相册保存后回读照片尺寸和 Live 类型。

界面新增覆盖：顶部标记不相交且不超出屏幕、大字体、照片/动态尺寸分别标注、保存后回到编辑器仍无重叠。另回归原 Live、导出和长图手势流程。

最终共 **78 个不同用例，78 通过，0 失败，0 跳过**：64 核心用例；iPhone 17 上 13 条 UI 流程；iPhone 16e 上 3 条 UI 流程（两条与 iPhone 17 重复）。两台模拟器均为 iOS 26.3.1。

核心记录为 `CoreFinal.xcresult` 与 `PhotoKitReadback.xcresult`，界面记录为 `UIPhone17.xcresult`、`UIPhone16e.xcresult`，按用例汇总见 `validation-summary.json`。相册回读明确请求原尺寸，避免将显示缩略图尺寸误当成已存照片尺寸；专项临时读取权限与用途说明仅在独立测试宿主中。截图见 `docs/version-screenshots/v4.0.6/`。
