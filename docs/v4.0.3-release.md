# 极拼 4.0.3（构建 7）

修复长图拼接时，照片区域的拖动被编辑手势占用、必须从侧边滚动条才能浏览的问题。主 App 与相册扩展版本统一为 4.0.3 / 7，最低 iOS 17，草稿 schema 仍为 4。

## 使用变化

- 纵向、横向及 Live 长图都可以直接在照片上单指滑动浏览，使用系统滚动的惯性与回弹。
- 轻点选择照片；双指平移、缩放和旋转照片；长按后拖动交换照片。
- 浏览不会修改照片或产生撤销记录，也不会自动选中路过的照片或切换工具面板。
- 文字和贴纸仍可直接拖动，画笔工具中拖动仍用于绘制；模板、自由和海报模式保持原有手势。
- 长图画布增加“单指滑动 · 双指调图”提示及相应辅助功能说明。

## 实现

`CanvasTouchRecognizer` 在长图照片或空白处的单指移动越过阈值时交出手势，使祖先 `UIScrollView` 正常接管滚动；双指与长按仍由编辑器处理。已经失败或取消的识别器不会在后续触点回调中重新启动编辑。

长图的照片选择延后到轻点或明确开始编辑时完成，并保持当前工具页，避免面板改变高度造成画布跳动。编辑仍使用原有坐标变换、预览缓存与一次手势一次撤销机制。

## 验证

最终共 **18 个不同测试取得通过结果**（9 个核心用例、4 个原模板手势用例、5 个长图用例）；5 个长图用例在 iPhone 16e / iOS 26.3 上再次全部通过。

回归涵盖：照片区域的纵向往返滑动、横向滑动与方向撤销、Live 长图浏览及原生预览导出、轻点与双指编辑后的浏览恢复、工具页保持、长按交换、原模板手势、画笔及核心坐标/缓存/历史记录。

- 旧手势代码对照：`build/Validation-4.0.3/BeforeFixPhotoSwipe.xcresult`。相同照片区域滑动不能移动内容，回归按预期失败。
- iPhone 17 / iOS 26.3：`GestureRegression.xcresult`，及修正多指撤销断言后的 `FinalGestureUndo.xcresult`。
- 较小屏幕复核：`SmallPhone.xcresult`。

UI 测试用导航与工具栏之间的可见区域定位触点。SwiftUI 的 ScrollView 辅助功能 frame 包含底部工具区，不能直接用它的归一化坐标当作照片区域。撤销断言比较每次实际手势前后的状态，避免将系统合成捏合产生的角度变化误认为撤销失败。

本轮为模拟器验证。真实照片、设备性能与用户操作手感仍以安装新 TestFlight 构建后的体验为准，不将模拟器运行时间当作真机帧率。
