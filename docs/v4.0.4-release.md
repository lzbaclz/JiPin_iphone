# 极拼 4.0.4（构建 8）

本版调整导出默认清晰度，并在相册保存完成后自动返回编辑器。主 App 和扩展均为 4.0.4 / 8，最低 iOS 17，草稿 schema 保持 4。

## 默认高清

- 新项目的导出偏好默认为高清：普通静态拼图最长边 4096、长图基准宽度 1440、Live 最长边 1440。
- Live 与静态图片共用项目清晰度设置，重新打开导出页时不再单独重置 Live 清晰度。
- 主动选择的标准尺寸及旧草稿里保存的设置继续保留；更改默认值不覆盖用户选择。
- Live 预览仍先生成较轻的 640 预览，真正保存或分享时再生成所选清晰度。长图超限处理与相册扩展的内存上限保持原有规则。

## 保存成功后自动关闭

普通图片、Live、从 Live 导出的静态图片，以及长图分页保存，都在 PhotoKit 确认写入成功后关闭整个导出流程并返回编辑器。通过回调传递到根导出入口，避免只关掉嵌套窗口中的最上层。

保存被拒绝、素材缺失、尺寸超限或系统写入失败时保留窗口与提示，不会把失败当成成功关闭。生成文件、分享与文件存储继续使用各自流程。

## 验证

最终 **71 个不同回归用例均取得通过结果**：

- 四种模式默认高清及明确标准设置的草稿编解码。
- 静态渲染、导出尺寸、GPS 元数据处理、分页及相册扩展尺寸保护。
- 普通和 Live 保存成功返回编辑器；Live → 静态、静态 → 分页的嵌套保存关闭完整流程。
- 在独立的新建模拟器中真实拒绝添加照片权限，确认导出窗口、错误提示和重试按钮保留。
- 4.0.3 的长图滑动专项仍通过。

首轮有一个界面断言未处理 iOS 把 `1440` 显示为 `1,440` 的千位分隔格式；统一数字显示格式后重跑通过，仍断言输出宽度为 1440。没有把首轮失败计作通过。

证据位于 `build/Validation-4.0.4/`：`ExportRegression.xcresult`、`DeniedPermission.xcresult`、`FinalExportFlow.xcresult` 与 `validation-summary.json`。最终截图见 `docs/version-screenshots/v4.0.4/`。这些是模拟器验证记录，不是真机录屏。
